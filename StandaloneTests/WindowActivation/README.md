# External window activation regression checks

Run `python3 StandaloneTests/WindowActivation/run.py` from the repository root.
An optional source-root argument checks these tests against an integration tree.

The runner compiles the actual production focus reconciliation and panel-sync
methods with simulated workspace, AX, and selection/layout boundaries. It checks
same-app and cross-app activation, idempotence, stale/reentrant notifications,
unrelated windows, drag/layout/termination guards, and active-Space filtering.
It records production source hashes and compiler/test output in a temporary folder.

These checks do not launch Tabbed or synthesize input. They do not verify actual
macOS AX delivery, window restoration, panel stacking, or SwiftUI interactions.
Manually group two windows, activate the hidden member from its application's
Window menu, and repeat with windows from different apps. Confirm the selected
tab and visible window change while preserving the group's frame.

Notification activation regression (#10): the suite also simulates a main-window
change while Chrome's focused-window attribute still reports the previously
selected tab. The live main-window query wins only for the frontmost process;
missing/unrelated main windows and later activation of another app remain safe.
Panel ordering and shared focused-group lookup use the same bounded preference;
checks include stale focus in another group and expiry back to ordinary focus.
A real Google Calendar notification is not generated by this test. Manually
verify notifications with Chrome already frontmost and with another app active,
for both an inactive grouped window and an ungrouped Chrome window.

Transient activation candidate (#14): a main-window notification can identify a
managed member even when both live AX attributes have already reverted to
another group's active window. The callback synchronously matches its element
with CFEqual against stored members of the same foreground process, validates
that member is still alive, and uses the existing guarded selection path. It
never retains notification targets for settled retries or enrolls new windows.
Ordinary focus/content events remain deferred and do not select their element.
The tests use CFString tokens to simulate AX element identity; real AX identity,
delivery ordering, window stacking, and Chrome behavior require manual checks.
Checks cover the captured stale-query/bounce sequence, live-state recovery,
identity/PID/liveness and existing safety guards, and reentrant selection.
Manual validation must start with a different Chrome window outside the target
group active, then open a Calendar notification for an existing tab in the hidden
member. Compare with a different app and another member of the target group active.
